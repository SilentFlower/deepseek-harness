# 初始化 DeepSeek Harness 开发规范

## 目标

让后续 Trellis 任务能够按代码职责找到本仓库的实际开发规则、源码示例和验证入口。

## 范围

- 整理 `.trellis/spec/`，覆盖 Harness 运行时、客户端、实验能力、应用入口、Python、原生代码、第三方源码、脚本、基准和文档网站。
- 以已有 `AGENTS.md`、架构、包 README、防御规则和测试策略为规则依据；提供经过读取核对的源码及测试链接。
- 保留 `.trellis/config.yaml` 的逐工作区配置，使包发现与最终索引一致，并修正无效的默认包键。
- 清除空模板、不适用的前后端分类和其他项目的通用示例。
- 按用户后续要求，将 CHK-001 的六处措辞同步到 `/root/project/flower-trellis` 的 Skill-Garden 源 Patch，并生成对应发布快照和平台编译产物。

## 约束

- 规范用中文书写；保留代码标识符、路径和工具要求的索引名称。
- 既有文档继续拥有详细规则；规范负责选读、局部示例和易错点，避免复制完整类型和生成目录。
- 不修改产品实现、公开接口、Session 格式、依赖或发布配置。
- 不改写 Trellis 的工作流或运行脚本；技能文档仅修复用户选定的 CHK-001 禁用术语，保持语义、管理标记和双平台副本一致。

## 验收标准

- [x] 每个配置范围和层都有可发现的索引，以及开发前阅读项和质量检查项。
- [x] 规范说明当前源码的组织、类型、生命周期、状态、错误和测试模式；不适用的内容不占位。
- [x] 每个专题都有真实源码、测试或规则归属文档支持，所有相对链接和锚点有效。
- [x] 所有原工作区均被配置范围覆盖；客户端和实验能力可进一步选读对应规则。
- [x] 规范树无初始化模板残留，索引与实际文件一致。
- [x] 完成规范专项验证、任务检查和适用的仓库文档检查，记录实际结果。
